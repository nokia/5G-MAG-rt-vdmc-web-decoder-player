# GPU reconstruction check

An interactive, cross-device test that verifies the SDK's **shader output** against the
native MPEG VMESH reference decoder — on desktop and on a real phone.

Unlike [`../verification/`](../verification/), which dumps the SDK's JS-side mesh and compares
it by symmetric RMSE, this test captures the vertices the GPU actually produces and matches
them **per displacement index** against the reference decoder's mesh. It is therefore the check
that catches driver-specific subdivision/displacement bugs (ANGLE, Adreno, Mali).

## What it does

1. `prep.mjs` produces the PC ground truth in `data/`:
   - `mesh.vmesh` — the stream under test
   - `decoded_0000.obj` — frame 0 as reconstructed by the native `decode.exe`, whose vertices
     are in global `dIdx` order
2. `test.html` loads the same `mesh.vmesh` through the real
   [`VDMCMeshStream`](../sdk/src/VDMCMeshStream.js) — no CPU/JS reconstruction anywhere — then captures
   every displaced vertex plus its `dIdx` through the shared
   [`../verification/gpu-capture.mjs`](../verification/gpu-capture.mjs), the same module the
   parity test and `run-verification.mjs` use.
3. GPU output `i` must equal `decoded_0000.obj[dIdx]`. PASS requires every decoder vertex to be
   covered and a mean error below 0.1% of the model diagonal.

Two capture paths, selected automatically:

| Path | Used on | Why |
|------|---------|-----|
| Transform feedback | desktop / ANGLE, Adreno | direct, exact |
| RGBA8 render-to-texture via [`GpuReadback`](../sdk/src/GpuReadback.js) | Mali (and `?rtt`) | transform feedback silently writes nothing on Mali; float render targets fail on both ANGLE and Mali, so each float is packed into one RGBA8 texel as its exact bit pattern over several passes |

Both paths are implemented once in the shared capture module and verified to agree bit-for-bit on
desktop (`?rtt` forces the readback path there).

## Requirements

- Node.js, and native `decode.exe` / `encode.exe` built from the MPEG TMM17 reference software
  in `tm-reference/bin/`, plus the reference configs in `tm-reference/cfg/`
  (see [`../verification/README.md`](../verification/README.md#requirements) for the expected
  layout and [`../docs/BUILD-WASM.md`](../docs/BUILD-WASM.md) for the build)
- Source frames for the football sequence when regenerating the stream with `prep.mjs`
  (`VDMC_INPUT_DIR`, see the verification README) — not needed if you pass an existing `.vmesh`
- A Chromium-based browser (WebCodecs HEVC)
- Python 3 for `serve.py` — the page needs its cross-origin-isolation headers, and it also
  provides the `/log` endpoint the test page forwards mobile console output to

## Run

```powershell
node verify/prep.mjs                  # encode + decode a fresh single-frame football stream
node verify/prep.mjs <path.vmesh>     # or use an existing stream (frame 0 only)

python serve.py 8097
# open http://localhost:8097/verify/test.html?dump
```

The single-frame default keeps the check quick: a multi-frame stream forces the SDK to decode
the whole texture + displacement video before frame 0's mesh is ready.

### On a phone

```powershell
adb reverse tcp:8097 tcp:8097
# open http://localhost:8097/verify/test.html on the device
```

Mobile implies `?dump` and `?rtt`, so the comparison runs automatically on load and console
output is forwarded to the `serve.py` terminal.

### Query parameters

| Parameter | Effect |
|-----------|--------|
| `?dump` | run the comparison automatically instead of waiting for the **compare** button |
| `?rtt` | force the RGBA8 readback path (implied on mobile) |
| `?vmesh=<url>` | override the stream (default `/verify/data/mesh.vmesh`) |
| `?dec=<url>` | override the ground-truth OBJ (default `/verify/data/decoded_0000.obj`) |

## Files

- `prep.mjs` — PC-side ground truth; reuses `encodeDecode()` from
  [`../verification/encode-decode.mjs`](../verification/encode-decode.mjs)
- `test.html` — the browser test page (viewer + capture + comparison)
- `data/` — generated by `prep.mjs`
- `screens/` — diagnostic screenshots, captured on demand and regenerable
